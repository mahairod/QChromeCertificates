# Chrome Certificate Policy Manager

Графическое приложение для Windows, управляющее изолированным набором доверенных CA-сертификатов в четырёх Chromium-браузерах:

- Google Chrome;
- Microsoft Edge;
- Brave;
- Chromium.

Приложение изменяет только политики текущего пользователя:

| Браузер | Раздел реестра |
| --- | --- |
| Chrome | `HKCU\Software\Policies\Google\Chrome` |
| Edge | `HKCU\Software\Policies\Microsoft\Edge` |
| Brave | `HKCU\Software\Policies\BraveSoftware\Brave` |
| Chromium | `HKCU\Software\Policies\Chromium` |

Настраиваются `CAPlatformIntegrationEnabled` и `CACertificatesWithConstraints`. Хранилища сертификатов Windows и встроенные корневые сертификаты браузеров не изменяются.

## Использование

1. Запустите EXE и выберите браузер. Для чтения и редактирования формы административные права не требуются.
2. Установите флажок «Изолировать браузерное хранилище сертификатов». Приложение подготовит `CAPlatformIntegrationEnabled=0`.
3. Добавьте CA-сертификат в формате CER, CRT или DER.
4. Дважды щёлкните сертификат и укажите разрешённые домены. Флажок «Автоматически включать поддомены» по умолчанию превращает `example.ru` в две записи: `example.ru` и `.example.ru`. При снятии флажка поле показывает точный полный список записей.
5. Нажмите «Применить». Если обычных прав для записи недостаточно, Windows покажет запрос UAC. Приложение сохранит политики, отправит браузеру сигнал обновления и покажет ссылку на его страницу policies.

Снятие флажка изоляции отключает редактор. Если в нём есть сертификаты, приложение запрашивает подтверждение. После применения обе политики выбранного браузера удаляются.

«Отмена» отбрасывает изменения и заново читает реестр. Выбор другого браузера заблокирован, пока есть неприменённые изменения. При закрытии окна такие изменения требуют подтверждения.

«Импорт» загружает переносимую JSON-копию в форму. Для записи в реестр после проверки нужен отдельный щелчок по «Применить». «Экспорт» сохраняет состояние формы. Закрытые ключи и личные сертификаты в файл не попадают.

Интерфейс доступен на русском и английском. При первом запуске язык определяется по языку интерфейса Windows. Выбранные язык, браузер и размер главного окна сохраняются рядом с EXE в `ChromeCertificatePolicyManager-settings.json`. Отсутствующий, повреждённый или недоступный файл настроек не мешает запуску.

Версия 2 не редактирует CIDR-ограничения из версии 1. Такие записи читаются без потери и помечаются предупреждением, но их нельзя изменить или применить в v2.

Ручной формат политик описан в [MANUAL-REGISTRY.md](MANUAL-REGISTRY.md).

## Сборка

Версия хранится только в `VERSION`. Команда `build.cmd` создаёт EXE с версией, манифестом и иконкой. Команда `verify-build.ps1` проверяет версию, манифест, DPI-awareness и иконку. Параметр `-RunSelfTest` дополнительно проверяет реестр, нормализацию доменов и CIDR старого формата, разворачивание поддоменов, определение организации издателя и резервную копию.

```text
ChromeCertificatePolicyManager.exe --self-test --registry-path Software\ChromeCertificatePolicyManager\Tests
```

Self-test использует временный раздел реестра и не изменяет политики браузеров. GUI/self-test не запускается в CI.

GitHub Actions собирает и статически проверяет EXE при каждом push и pull request. Тег `v<VERSION>` создаёт GitHub Release с EXE и контрольной суммой SHA-256.
